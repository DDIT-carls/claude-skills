# 命理 / 算命 / 运势 / 缘分技能

这个技能把两件事分开处理：**算数**交给确定性的历法计算脚本，**解读**交给你
（Claude）用命理知识和文笔组织成好读的中文内容。这样既保证干支、八字、
老黄历这些"硬数据"是真实准确的（而不是模型现编的），解读部分又能保持
自然流畅、因人而异。

## 什么时候用

- 用户给出生日期（阳历或农历均可，若是农历告诉 Claude 是农历即可）想算命、
  看八字、看性格、看运势。
- 用户想知道今天/这周/这个月/今年运势如何，是否要结合出生日期个性化。
- 用户想测两个人的缘分、合婚、配对（可以是恋爱关系，也可以是友情/合伙）。
- 用户想查某天的老黄历（宜忌、黄道吉日、财神/喜神/福神方位、冲煞）。

如果用户没给出生日期但想算命/合婚，先问清楚：出生的阳历年月日（时辰可选，
没有时辰也能算，只是精度会打折扣，需要提醒一句）。

## 使用流程

### 第一步：调用计算脚本拿到真实数据

脚本路径：`scripts/fortune.js`（Node.js，已内置 `scripts/lunar.js` 依赖库，
无需额外安装任何包，直接 `node` 运行即可）。三个子命令：

```bash
# 1. 个人命盘（八字/五行/十神/星座/生肖/星宿/彭祖百忌）
node scripts/fortune.js natal --date 1995-08-17 --time 14:30 --gender male
# --time 和 --gender 可省略；不知道出生时辰就不传 --time

# 2. 今日/指定日期运势（老黄历宜忌 + 可选：结合某人出生日期做个性化关联）
node scripts/fortune.js daily --date 2026-08-17 --birth 1995-08-17 --time 14:30
# --date 省略则默认今天；--birth/--time 省略则只返回当天通用老黄历信息

# 3. 两人缘分/配对（生肖关系 + 星座元素关系 + 八字日主五行生克）
node scripts/fortune.js match --date1 1995-08-17 --time1 14:30 --date2 1996-02-03 --time2 08:00
```

所有命令都把结果打印为 JSON（stdout）。日期格式固定 `YYYY-MM-DD`，时间格式
`HH:mm`。这一步只是取数，**不要**把原始 JSON 直接甩给用户。

### 第二步：把 JSON 组织成解读文案

打开并参考 `references/interpretation-guide.md`——里面详细说明了：
- 命盘（`natal`）结果怎么组织成性格/命理解读
- 运势（`daily`）结果里的五行生克怎么转换成"今天适合做什么/要注意什么"
- 缘分（`match`）结果的三个维度（生肖/星座/日主五行）怎么综合表达，
  以及如何避免"论断式"的负面措辞
- 关于"本周/本月/本年"这种没有单独命令的周期性运势，如何用 `daily`
  取样代表性日期来推演

**务必先读这个指南再动笔**，尤其是措辞基调部分——命理解读要有温度、给
建设性建议，不要写成宿命论断或制造焦虑。

### 第三步：输出

默认用自然的中文段落/小标题呈现即可，不必强行套用表格。如果用户想要更
视觉化的呈现（命盘图、运势卡片），可以用 Visualizer 工具把结构化字段
（四柱、五行、生肖、星座等）做成一张图。如果用户要保存/分享这份结果
（比如"帮我做成一份PDF/图片"），才需要用文件工具生成对应格式的产物。

## 重要说明

- 脚本计算的干支、八字、老黄历宜忌、五行生克等**均为真实历法/传统命理规则
  计算结果**，不是编造的；但基于这些数据的"运势好不好""是否有缘分"等
  **解读和建议属于传统文化娱乐范畴**，不代表科学结论，回复中自然带出这层
  分寸感即可，不必每次都大段免责声明。
- 涉及生老病死、婚姻决策等严肃话题时，可以提供命理角度的参考视角，但避免
  替用户做重大人生决定，更不要用命理结果去加重用户的焦虑或恐慌。
- `Horoscope` 参考项目中的每日星座运势原本依赖一个已不可访问的第三方接口，
  本技能不会也不需要请求它——星座运势文案由 Claude 结合真实的星座/日期
  数据自己原创撰写（见解读指南最后一节）。
